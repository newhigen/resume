# 재편 결정 기록

## 2026-08-07 — 구조·이름 결정

### 출발점

sungd.uk 아래 사이트 넷. 루트를 에세이 블로그가 쓰고 있어 tech·resume·ai 가 그 자식처럼 보이는데 실제론 형제다. 어디에도 서로를 가리키는 동선이 없어, 한 사이트에 들어온 사람이 나머지를 못 본다.

세어본 규모:

```
writing (sungd.uk)       글 67편 + 초고 17편        활발 (최근 커밋 06-12)
tech    (tech.sungd.uk)  기술 글 12편 + 프로젝트 14  마지막 글 04-04, 넉 달 멈춤
resume                   이력서 한 장
ai-pick                  큐레이션 페이지 하나 (매일 자동 갱신)
```

### 루트를 허브로, 단 링크트리는 안 만든다

루트는 가장 좋은 주소다. 링크만 있는 페이지를 올리면 체류 0초짜리 중계로 그 자리를 쓰는 셈이라, 소개와 프로젝트가 실린 "그 자체로 목적지인 홈"으로 간다.

허브보다 싸고 효과 큰 건 각 사이트 상단에 서로를 가리키는 링크 한 줄을 공통으로 넣는 것. 홈을 만들어도 이게 없으면 왕복이 안 된다.

### tech 는 내리지 않고 해체한다

"내용 없으니 내리자"가 처음 생각이었는데, 세어보니 프로젝트 소개 14개(career-radar·claude-watch·whooing-tools·worklog-dashboard 등)가 이력서 근거로 그대로 쓸 자산이었다. 내리면 그게 사라진다.

대신 멈춘 사이트를 억지로 살리지 않고 안 멈춘 곳에 얹기로 했다. 기술 글 12편은 writing 으로, 프로젝트는 루트로. 앞으로 기술 글을 써도 writing 한 군데만 굴리면 된다.

### 이력서는 루트에 안 올린다

루트 = 이력서면 "sungd.uk 보세요" 할 때마다 구직 신호로 읽히고 개인정보가 그냥 노출된다. 루트는 소개+프로젝트까지만, 이력서는 resume. 에 남긴다.

### 새 repo 를 안 만들고 newhigen.github.io 를 개조한다

루트 사이트에 필요한 것(프로젝트 콘텐츠, Astro 셋업)이 이미 그 repo 에 다 있다. 기술 글만 덜어내고 홈을 다시 쓰면 되므로 새로 만들 게 없다. 대신 Netlify 로 옮긴다 — GitHub Pages 는 301 리다이렉트를 못 걸어서, 옛 링크를 살리려면 Netlify 가 필요하다.

### ai. → today.

`ai` 는 너무 넓다. 주소만 보면 AI 관련 뭐든 있을 것 같은데 실제론 한 가지만 한다. 후보로 pick(고른다·repo 이름과 맞음), cc(Codex 도 다루는데 좁다), tools(큐레이션 성격이 안 산다), changelog(raw 목록 인상) 를 놓고 `today` 로 정했다. 매일 새벽 5시 20분 자동 갱신이고 첫 섹션이 "오늘 써볼 기능"이라 하는 일과 맞는다.
